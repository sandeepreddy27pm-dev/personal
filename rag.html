Step 01

Collect the Knowledge Base

RAG begins with the information the system should be able to answer questions about.

Raw knowledge

Documents can come from PDFs, websites, databases, Word files, internal wikis, support tickets, APIs, images, diagrams, etc.

↓

Important distinction

The LLM itself is not being retrained here. We are giving the LLM external knowledge at inference time.

Think of it as: "Don't teach the LLM permanently. Give it the relevant pages when the user asks a question."
Step 02

Chunk the Documents

Large documents are split into smaller pieces that can be independently retrieved.

Step 03

Generate Embeddings

Each chunk is transformed into a numerical representation of its semantic meaning.

Step 04

The embedding, original text and metadata are stored together.

A vector database normally stores much more than the vector itself. The original chunk and metadata are critical for retrieving usable context.
Step 05

User Query

The user asks a question. In production systems, query rewriting may happen before retrieval.

The original user query doesn't go directly to the vector database. It is first converted into a representation that can be compared with document embeddings.
Step 06

Embed the Query

The query is converted into an embedding using the same compatible embedding model.

↓

Query embedding

Important: the document embeddings and query embedding need to live in a compatible embedding space. Usually this means using the same embedding model.
Step 07

Retrieve Relevant Chunks

The system compares the query with stored vectors and retrieves the most relevant candidates.

Search type
Vector
Top K
5
Nearest neighbour ≠ guaranteed correct answer. Vector similarity is a relevance signal, not proof that a chunk contains the answer.
Step 08

Reranking

A reranker can inspect retrieved candidates more deeply and reorder them before sending them to the LLM.

Why rerank?

Vector search is optimized for fast candidate retrieval. A reranker can perform a more expensive relevance calculation on a smaller set of candidates.

A common production architecture is: retrieve Top-20 → rerank → send Top-5 to the LLM.
Step 09

Augment the Prompt

The retrieved context is inserted into a prompt alongside the user's question and instructions.

This is the key RAG trick: retrieve first, then generate.
Step 10

LLM Generation
